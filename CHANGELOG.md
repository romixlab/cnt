# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). All crates in the workspace (`cnt`, `cnt_macro`, `cnt_core`,
`cnt_cli`) share one version.

## [0.4.0] - 2026-09-29

### Breaking changes

- Counter format version 2: `cnt_cli` 0.4 requires firmware built with `cnt` 0.4, and vice versa.
- Locations come from the macro call site (`proc_macro::Span::file`/`line`, Rust 1.88+) instead of DWARF: `cnt_core`
  no longer depends on `gimli`, `Location` is `{ file: Arc<String>, line }` (the compiler's view of the path, e.g.
  relative to the workspace), there is no module path and no `<unknown location>`.
- `cnt_core`: `Counter::buf` replaced by `idx` (word index) and `addr`; `Ty::len()` (bytes) replaced by `bytes()` and
  `words()`; `Storage::RAM`/`BKP` renamed to `Ram`/`Bkp`; `Counter::location` is not optional; `Counter::layout` and
  `Counter::qualified_name()` added; `CountersBlock::used_bytes()` and `Counters::blocks()` added.
- Marker symbol names are JSON objects with a `kind` member, `storage` is `ram`/`bkp`, `crate_name` renamed to `crate`.

### Added

- `cnt!` and `bkp_cnt!` count unconditionally, without a `true` argument: `cnt!(packet_count: u32)`.
- Instance counters: `#[derive(cnt::Count)]` on an enum with `#[count(u64, unit = "B", warn)]` variant attributes,
  `cnt::counters!(Type, name)`/`cnt::bkp_counters!(Type, name)` in a `static`, and `Counters<E>::count`, `count_if`,
  `add`. A library taking `&'static Counters<E>` gets separate counters per instance, named by the firmware.
- On cores with `target_has_atomic = "32"` (Cortex-M3 and up) counters are updated with `fetch_add`/`fetch_update`,
  so an update preempted by an interrupt updating the same counter is retried instead of lost. Cores without (thumbv6m)
  keep the plain load-add-store.
- `disabled` feature of `cnt`: macros expand to nothing, `Counters<E>` is a zero-sized no-op, no buffers or marker
  sections are emitted and `cnt.x` is empty. `cnt::DISABLED` constant.
- Counter markers are `#[used]`, a `cnt_if!` whose condition is optimized out still appears in host tools.
- `cnt_cli` shows counters as `group/name` and instance counters as `instance/Variant`, with the crate and `Count` type
  in the location line.

### Fixed

- The disambiguator of otherwise identical invocations includes the call site's file, line and column, instead of
  relying solely on the unstable `Debug` output of `Span`.

## [0.3.0] - 2026-09-29

### Breaking changes

- `cnt::counters_ram_buffer()` and `cnt::counters_bkp_buffer()` return `&'static [AtomicU32]` instead of
  `&'static [u32]`. Read values with `word.load(Ordering::Relaxed)`. A shared slice of plain `u32` over memory that
  interrupts keep writing to was undefined behaviour.
- `cnt.x` is now generated by the `cnt` build script and asserts at link time that all counters fit into the buffers.
  Firmware with too many counters fails to link with `cnt: too many RAM counters ...` instead of corrupting memory or
  panicking at runtime.
- `bkp_cnt_if!` requires a `BKPSRAM` memory region in `memory.x` (or `CNT_BKP_MEMORY_REGION` set to an existing
  region) when `CNT_BKP_BUFFER_SIZE_WORDS` is non-zero. Previously the BKP buffer silently ended up in `.bss` and was
  zeroed on every reset.
- `cnt_cli` reports an error instead of panicking when the counters in an ELF do not fit into the buffer.

### Added

- `+= <expr>` is optional in `cnt_if!`/`bkp_cnt_if!`, `cnt_if!(true, packet_count: u32)` counts by 1.
- Trailing commas are accepted in the macros, leftover tokens are reported instead of ignored.
- `_CNT_SIGNATURE` contains a magic and a format version, checked by `cnt_cli`. Firmware built with 0.2.0 (all-zero
  signature) is still accepted.
- `cnt_cli` verifies that the `.counters_ram`/`.counters_bkp` sections are placed at address 0 by the linker script.
- `cnt_cli`: probe and target selection like the probe-rs CLI (`--probe`, `--protocol`, `--speed`,
  `--connect-under-reset`, `--chip-description-path`, `PROBE_RS_*` environment variables), interactive probe selection
  when several are connected.
- `cnt_cli`: `--chip` is taken from a `probe-rs run --chip <CHIP>` runner in `.cargo/config.toml` when omitted.
- `cnt_cli`: the ELF path can be omitted inside a cargo project, the most recently built binary is used.
- `cnt_cli`: `--version`, styled help, shared colour theme for the CLI and TUI with a 16-colour fallback.
- TUI shows BKP counters in a second table, defmt-style locations relative to the current directory, severity icons,
  and highlights recently changed values. `r` resets RAM counters, `R` BKP counters.
- Documentation: non-volatile counters setup, limitations of lock-free counting when one call site runs in several
  contexts, that the dependency must be named `cnt`.

### Fixed

- Soundness: counter updates no longer create `&mut` references to the buffers, so an interrupt updating one counter
  while another update is in progress is not undefined behaviour. u64 counters are accessed as two aligned u32 words
  instead of through an unaligned `*mut u64`.
- Soundness: the u64 increment functions used unchecked pointer arithmetic; an out-of-bounds counter index wrote past
  the buffer. They now panic like the u32 ones (and cannot be reached with the linker script asserts).
- Macro hygiene: the generated code introduced a local `counter_idx`, shadowing a user variable of the same name used
  in the `+=` expression. The generated code refers to `::cnt` explicitly.
- The unknown-severity error points at the severity token instead of the type.
- `_CNT_SIGNATURE` was a `static mut` in `.rodata`, producing a `LOAD segment with RWX permissions` linker warning.
- Location lookup is best-effort: a compilation unit without a line program or an odd DWARF entry no longer fails
  loading the whole ELF, the affected counter is listed with `<unknown location>`.
- `cnt_cli` no longer aborts when DWARF variable names or a `FileIndex` are unusual.
- README: `Cargo.toml` typo, `as u32` missing in the expression example.

## [0.2.0] - 2026-09-06

### Added

- `_CNT_SIGNATURE` static, reserved for identifying the counters format.
- TUI demo and expanded README.

### Fixed

- macOS host builds (section names).

### Changed

- Workspace-level dependency versions.

## [0.1.0] - 2026-07-19

Initial release, extracted from `embedded_bedrock`.

### Added

- `cnt_if!` and `bkp_cnt_if!` macros for `u32` and `u64` counters in a RAM or non-volatile buffer, with an optional
  `+= <expr>` amount, unit, severity (`error`, `warn`, `info`, `debug`, `trace`) and group.
- Unique counter indices assigned by the linker via the `cnt.x` linker script, buffer sizes configurable with
  `CNT_RAM_BUFFER_SIZE_WORDS` and `CNT_BKP_BUFFER_SIZE_WORDS`.
- `counters_ram_buffer()` and `counters_bkp_buffer()` for sending counters from the firmware.
- `cnt_core`: ELF parsing of counter symbols and DWARF locations (based on defmt).
- `cnt_cli`: `list`, `read`, `reset` and a ratatui-based `tui` reading counters from a target with probe-rs,
  human-readable byte values.
